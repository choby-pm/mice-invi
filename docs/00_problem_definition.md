# 00. 문제 정의 v1.0

> 이 문서는 최초 기획·설계 기준입니다. 현재 구현 범위와 이후 변경은 [현재 상태](current-status.md)를 확인하세요. 기획 확정은 전체 개발 완료를 뜻하지 않습니다.

> 대화로 진행한 문제 정의 단계(사용자 정의 → 병목 파악 → 대상 선정 → 수동/자동 경계 → 핵심 KPI)의 확정본입니다. 이후 모든 문서의 출발점입니다.

## 문제 한 문장

해외 VIP와 동반자에 관한 잦은 변경이 PCO 초청 담당자 한 명과 엑셀 파일을 거쳐 수동으로 전파되면서, 공유 지연과 누락이 의전 사고와 담당자의 과도한 스트레스로 이어진다.

## 제품 형태

여러 PCO가 여러 행사에 반복 사용하는 **SaaS**. 구조는 `PCO(테넌트) → 행사 → 초청자`. 행사 규모는 동반자 포함 보통 20~200명이며 그 이상도 가능 (설계 기준 500명).

## 1. 사용자

| 그룹 | 역할 | 권한 |
|---|---|---|
| **PCO 초청 담당자** ⭐ 핵심 페르소나 | 초청자 생성, 변경 관리, 업체 배포, 최종 확정 | 행사 단위 전체 관리 |
| PCO 관리자 | 행사 생성, 담당자·업체 초대, 권한 설정 | 테넌트 관리 |
| 주최측 | 현황 조회, PCO에 요청 하달 | 조회 + 요청 등록 (직접 수정 불가) |
| 진행 업체 | 담당 분야 정보 조회·등록 | 플랫폼 레벨 계정, 참여 행사의 담당 분야만 |
| 대리인 (비서·대리인) | VIP·동반자·수행원 정보 입력 | 담당 대표단 한정. VIP 본인은 직접 입력하지 않음 |
| VIP·동반자·수행원 | 데이터 주체 | 로그인 안 함 |
| 현장 스태프 | 모바일로 조회 | 조회 전용 (쓰기는 고도화) |

## 2. 병목

핵심: **잦은 변경이 한 사람과 엑셀 한 파일을 거쳐 수동으로 전파된다.**

1. 변경 유입 경로가 여러 곳 (대리인 메일, 주최측 전화, 업체 회신)
2. 변경의 영향 범위를 사람이 기억으로 판단
3. 전파 여부와 반영 여부를 추적할 수 없음
4. 변경 이력이 남지 않아 사고 원인 추적·인수인계 불가
5. 모든 정보가 담당자 1인에게 집중 (그 사람이 빠지면 행사가 멈춤)

## 3. 대상 (MVP 핵심)

- VIP·동반자·수행원에 한정 (일반 참가자 등록은 제외)
- **요청 데이터와 확정 데이터의 분리** (대리인은 요청, 업체는 확정)
- **변경 이슈 단위의 N차 연쇄 관리와 상태 보드** — 변경 하나가 2차·3차·4차로 번지는 조정 항목을 트리로 묶고, 상태를 한눈에 관리
- 업체의 "반영 완료" 확인까지 추적
- 민감정보(여권·건강·종교) 수집은 MVP 포함, 보안 기본선과 분리 동의도 MVP 포함

## 4. 수동/자동 경계

| 구분 | 항목 |
|---|---|
| 자동 | 변경 이력 기록, 영향 업체 식별, N차 예상 영향 전개와 무효화, 1·2차 이후 알림, 미입력·미확인 독촉, 파기 |
| 반자동 | 변경 요약 생성, 명단 간 불일치 탐지, 배차 제안 |
| 수동 | 의전 등급 결정, 판단 노드 결정(예: 만찬 참석 가능 여부), 정정 요청, 해당 없음 처리, 정산 완료 처리, 업체의 반영 확인 |

원칙: **"업체에 알렸다"와 "업체가 반영했다"를 분리해서 추적한다.**

## 5. KPI

| 유형 | KPI |
|---|---|
| North Star | VIP 의전 사고율 (픽업 누락, 객실 오류, 식이 누락 등) |
| 선행 | **변경 이슈 종결 리드타임** (최초 변경 → 마지막 하위 항목 완료) |
| 선행 | **행사 시작 시점 미종결 이슈 수** (목표 0) |
| 선행 | 필수정보 완결률 (D-14, D-7) |
| 담당자 | 담당자 1인당 관리 인원, 엑셀·이메일 수작업 건수, 업무 스트레스(설문) |
| 사업 | PCO 재사용률 (두 번째 행사를 이 제품으로 여는 비율) |

## 주요 결정 (문제 정의 단계)

| 주제 | 결정 |
|---|---|
| 항공 변경 흐름 | 대리인은 출발지·도착지·귀국지만 수정 → PCO·항공 업체 알림 → 업체 재예약 → PCO·대리인 알림 |
| PCO 승인 | 업체 재예약에 PCO 승인 불필요. PCO는 정정 요청 가능 |
| 2차 이후 알림 | 필수 기능. 3차·4차 연쇄까지 고려 |
| 업체 계정 | 플랫폼 레벨 계정 1개로 모든 프로젝트 확인. PCO는 즐겨찾기 후 행사에 추가 |
| 동의 | 입력 시 정책·공지 체크 (개인정보 동의서 형태) |
| 유입 | 이메일 또는 행사 페이지 직접 유입 |
| 접근 차단 | PCO가 정산 완료 처리하는 시점부터 업체 접근 차단 |
