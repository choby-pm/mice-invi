# 현재 구현 상태

기준일: 2026-10-20. 기능 기준 커밋: `05b9845`(디자인), `f3ce1c3`(항공 여권). 서비스: https://miceinvi.vercel.app

## 제품 목표

PCO는 전체 현황과 대응할 문제를 쉽게 파악하고, 업체는 자기 업무의 최신 고객 입력을 받아 처리하며, VIP 측은 자기 대표단의 결과를 빠르게 확인합니다. 범위 밖 데이터는 서버·DB에서 차단합니다. 변경 확인과 실제 예약 반영 완료는 구분합니다.

## 구현 범위

| 영역 | 현재 동작 |
|---|---|
| 행사·명단 | 행사·대표단·참가자·전체 명단, 팀·행사 설정 |
| 서비스 | 항공·숙박·수송·공항 의전·식음 요청/처리 결과, 배정, 상세 팝업, 처리 내역 |
| 연동 | 요청과 확정 분리, 항공 확정에 따른 수송 생성, 일부 변경 영향의 조정 항목 생성 |
| 변경 대응 | 변경 전후·개인 확인·업체 확인·기본 24시간 확인 기한, 운영 지표·불일치 점검, 유휴 시 15초 갱신 |
| 취소·정산 | 불참 시 예약 보존·취소 요청, 업체 취소 반영, 미완료 정산 차단, 정산 후 업체 접근 종료 |
| 대리인 | 배정 대표단만 조회·입력, 참석·동의·요청·예약·일정 회신, 안내·일정 조정 내역 조회 |
| 일정 | 하위 행사·대상 지정·공개 범위·확정·취소·회신, 자체 일정 관련 1차 구현 |
| 민감정보 | 행사별 암호화·명시적 열람·기록·동의 확인·파기. 항공 업체에는 배정 발권 대상의 여권 관련 필드만 제공 |
| 디자인 | 프리텐다드 자체 제공, 표·상세 가독성, PCO 대응/오늘 일정 2열, 업체 업무 우선 배치 |

PCO·업체·대리인은 Supabase 인증을 사용합니다. 공개 데모 버튼은 제한된 전용 계정으로 입장합니다. `/admin`은 데모용 임시 인증이며 플랫폼 운영사 실제 인증은 완료되지 않았습니다.

## 검증·데이터

- DB 마이그레이션 `0001`~`0039` 적용 기준. 배포와 DB 변경은 별도 절차입니다.
- 기능 작업에서 전체 자동 테스트 168개·배포 빌드 통과. 독립 조직으로 업체·대표단 격리, 동의, 열람 기록, 파기, 예약 보존 확인.
- 배포 화면에서 PCO 운영 현황, 항공 업체 상세·가상 여권 3명 열람, 프리텐다드 로드 확인.
- 데모 행사 3개·대표단 6개·참가자 18명·서비스 31건 유지. 공유 데모 사용 이후 수치는 달라질 수 있습니다.
- 근거: [운영 흐름](reviews/operational-flow-2026-10-20.md), [여권](reviews/flight-passport-2026-10-20.md), [가독성](reviews/dashboard-readability-2026-10-20.md).

## 우선 후속 과제

| 우선순위 | 과제 | 이유 |
|---|---|---|
| 실제 운영 전 | 공유 데모와 실고객 환경 분리, 데모 비활성화 검증, 플랫폼 운영자 실제 인증 | 데모 입장을 실제 운영 권한으로 사용하면 안 됨 |
| 실제 운영 전 | 백업·복구·보관 기한·자동 파기 절차 검증 | 기능 검증이 운영 자동화를 보증하지 않음 |
| 높음 | 미접속 업체 대상 메일·문자·재알림·에스컬레이션 | 현재 인앱 변경함·화면 갱신 중심 |
| 높음 | 예약 여러 테이블 저장의 원자성·동시 편집·재시도 | 일부 저장 뒤 후속 실패가 가능한 경로 존재 |
| 높음 | 행사별 발권 필수 필드·누락 정보·기한 설정 | 미입력 생년월일·성별 등을 임의 생성하지 않음 |
| 다음 | 영향 규칙 확대·설정화, 변경함 전체 검색·페이지 이동 | 모든 기획 규칙·대규모 이력 탐색은 미완성 |
| 다음 | 일정표 PDF/엑셀, 외부 예약·메시지 연동 | 현재 내부 업무 기록 중심 |

기획의 Outbox·큐, 전체 자동화, 가용성·복구 목표, 모든 연쇄 규칙은 설계 목표이며 전체 구현 완료가 아닙니다. 법률 검토·대규모 부하·외부 침투 시험도 수행하지 않았습니다.
