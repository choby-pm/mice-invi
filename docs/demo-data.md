# 데모 데이터 v1

기존 샘플과 별개인 **[DEMO] 글로벌 의전 운영팀** 조직에 생성합니다. 실제 사람·예약·여권 정보는 포함하지 않습니다. 앱 화면이나 권한 정책은 변경하지 않습니다.

## 실행

현재는 데모 모드가 기본입니다. `/login`, `/console-login`, `/vendor-login`, `/portal-login`에서 역할 버튼을 누르면 비밀번호·이메일 인증번호 없이 전용 데모 계정으로 입장합니다. 플랫폼 운영자는 기존 내부 도구 화면으로 입장합니다. 일반 로그인·가입·인증번호 발급은 데모 모드에서 중지됩니다. 원래 로그인으로 되돌리려면 실행 환경에 `DEMO_MODE=false`를 설정하고 재시작/재배포합니다.

역할 버튼도 실제 Supabase 연결과 아래 데이터 생성이 필요합니다. DB 연결 실패나 계정 누락 시 오류를 표시합니다. 데모 이메일·관리자 메타데이터·조직/업체/대표단 연결을 서버에서 검사하며, 데모 외 조직에도 연결된 계정은 입장을 거부합니다. 토큰과 관리자 키는 브라우저로 보내지 않습니다. 공용 데모 계정이므로 체험자들의 수정 내용은 공유됩니다.

```sh
npm run seed:demo             # 생성 목록만 미리보기 (DB 연결 없음)
npm run test:demo             # 데이터 관계·기능별 구성 검사 (DB 연결 없음)
npm run seed:demo -- --apply  # .env.local의 Supabase에 실제 생성
```

DB에는 `supabase/migrations/0001`부터 `0030`까지 적용되어 있어야 합니다. `.env.local`의 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`가 필요합니다. 새 계정 비밀번호는 실행 시 무작위 생성해 터미널에 한 번 표시합니다. 직접 정하려면 실행 환경의 `DEMO_PASSWORD`를 설정합니다. 비밀번호와 관리자 키를 저장소에 커밋하지 마세요.

| 접점 | 이메일 | 진입 경로 |
|---|---|---|
| PCO 관리자 | choby.pm+demo-pco@gmail.com | `/console-login` |
| PCO 담당자 | choby.pm+demo-manager@gmail.com | `/console-login` |
| 현장 조회 직원 | choby.pm+demo-field@gmail.com | `/console-login` |
| 항공 담당 업체 | choby.pm+demo-vendor@gmail.com | `/vendor-login` |
| 베트남 대표단 대리인 | choby.pm+demo-proxy@gmail.com | `/portal-login` |

기존 개발 계정은 사용하지 않습니다. 현재 앱은 PCO 계정당 조직 하나를 선택하므로 별도 데모 계정으로 로그인합니다. 계정 생성·데모 입장 시 메일은 발송하지 않습니다. `DEMO_MODE=false`일 때만 원래 비밀번호 로그인·대리인 이메일 인증번호 로그인을 사용합니다.

## 재실행과 제한

고정 ID로 누락된 행만 추가하며, 이미 존재하는 데모 행·계정 비밀번호는 유지합니다. 대표단 생성 트리거가 만든 빈 서비스 항목만 처음에 데모 값으로 초기화합니다. 실패 후 재실행할 수 있지만 여러 REST 요청에 걸치므로 전체 생성이 하나의 트랜잭션은 아닙니다. 동시에 여러 번 실행하지 마세요. 재실행은 삭제했던 데모 행을 다시 만들 수 있으므로 완전 초기화 용도로 사용하지 마세요. 민감정보 열람 기록은 실행할 때마다 추가됩니다.

날짜는 재현성을 위해 **2027년 3월 1~4일**로 고정했습니다. 상태별 화면 시연을 위한 초기 데이터이므로 과거의 행동 API 호출 이력을 재생하지는 않습니다. 생성 이후 버튼 동작은 기존 앱 로직을 그대로 사용합니다. 메시지함은 기존 게시 안내문·일정 조정 요청을, 업체 처리 내역은 기존 서비스·조정 결과를 조회합니다. 별도 채팅이나 메일 발송 데이터는 생성하지 않습니다. 외부 항공·호텔·문자 서비스에는 아무 요청도 보내지 않습니다.
