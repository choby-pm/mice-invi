# 고객 입력 연동·업체 상세 및 가독성 개선 — 2026-10-20

## 요청과 구현

- 고객 입력을 담당자·업체·고객 화면에서 함께 확인하도록 연결.
- 업체 목록을 최대 폭이 있는 업무 공간, 상태별 건수, 대표단/노선/편명 검색, 대표단별 카드로 재구성. 작은 표의 잘린 요약을 상세 팝업으로 대체.
- 상세 팝업에서 고객 요청과 업체 처리 결과를 구분. 항공 도시/공항/희망일/메모, 예약·발권·구간·예약번호, 숙박 객실 구성/배정, 수송 탑승/차량/기사, 공항 의전, 식이 요청, 관련 참가자 표시. 암호화된 여권·건강정보를 자동 열람하지 않음.
- 업체 홈·처리 내역, PCO 서비스 현황, 대리인 대표단 상세는 공통 조회 항목과 상세 화면 사용. 업체 확정 결과가 대리인에게도 표시됨.
- 대표단 생성/업체 추가 후 분야별 전체 대표단 담당 업체가 한 곳일 때 미배정 DRAFT/REQUESTED 항목만 자동 연결. 기존 배정은 보존. 복수 업체는 PCO가 서비스 현황에서 직접 선택. 현장 직원에게 배정·추가·삭제 버튼 비노출, 저장 권한도 서버 검사.
- 고객이 확정된 항공/숙박/식이 요청을 변경하면 CHANGING 표시. 기존 예약/발권은 유지하고 이전 확정 결과라는 안내 표시. 동일 내용 재저장은 상태 유지. 취소·지원 제외 요청 수정 차단.
- 요청 메모를 목록 요약에 포함. 요청 저장 실패를 성공으로 숨기지 않음. 식이 정보는 참가자 소속을 확인한 뒤 갱신하고 잘못된 JSON으로 기존 내용을 삭제하지 않음.
- 참석 회신을 불참에서 참석으로 바꿀 때 대표단의 불참 상태도 해제. 참가자/일정/동의/요청/확정 저장 후 세 접점의 관련 경로 갱신. 다른 사용자가 열어 둔 화면은 새로고침 또는 재진입 시 최신 내용 확인.
- 일시 입력/표시를 서울 GMT+9 기준으로 왕복. 기존 UTC 값을 잘라 입력란에 넣던 문제와 재저장 시 9시간 이동, 날짜 경계 표시 오류 수정.
- 예약/객실/배차/의전 확정 시 새 데이터를 검증·삽입한 후 이전 행 정리. 빈 입력이나 삽입 실패로 기존 예약을 먼저 지우지 않음.

## 검증

- 전체 테스트 128개, 타입 검사, 운영 빌드, 변경 파일 ESLint 통과.
- 독립 테스트 조직·행사·대리인·업체로 실제 서버 액션과 Supabase RLS 검증: 대표단 생성 → 자동 배정 → 고객 항공 요청 → 업체 요청 조회 → 예약/발권 확정 → 고객 확정 조회 → 입국/귀국 수송 2건 생성 → 고객 변경 요청 → 예약 보존/CHANGING → 업체 재확정 시 중복 없는 구간 교체. 숙박 메모·참가자별 식이 전달도 확인. 테스트 데이터는 정리하며 기존 데모 조직은 사용하지 않음.
- Chrome 실제 브라우저에서 업체 로그인, 편명 검색, 상세 팝업 열기/닫기, 요청과 발권 구간·참가자 표시, 390×844 모바일 배치 확인. 확정 편집창이 서울 기준 입국 09:00/13:00, 귀국 11:00/15:00으로 열리는 것 확인. 공용 데모의 예약 저장 버튼은 누르지 않음.
- 데모 행사 3개·대표단 6개·참가자 18명·서비스 31건 보존. 시드 재실행/DB 마이그레이션 없음.

## 남은 범위

- 고객 요청 변경이 외부 항공/호텔의 실제 예약을 자동으로 바꾸지는 않음. 업체가 이전 확정과 새 요청을 확인해 다시 처리하는 흐름.
- 웹소켓 기반 실시간 알림·동시 편집 잠금은 포함하지 않음. 확정 상세 교체는 여러 REST 요청으로 수행하므로 완전한 DB 트랜잭션은 아님. 동시 편집이 필요해지면 트랜잭션 함수로 전환.
- 의전 등급·지원 정책 변경에 따른 기존 예약의 일괄 재계산/자동 취소와 전체 영향 규칙 확장은 포함하지 않음.
