# 역할별 데모 검증 — 2026-10-19

기준 커밋: `de40ee1`. 작업 전 저장소에 미커밋 변경 없음.

## 확인 방법과 결과

- Supabase 실제 연결 정상. 시드 재실행·초기화 없이 데모 조직의 행사 3개, 대표단 6개, 참가자 18명, 서비스 31건 확인.
- 운영 사이트의 로그인 HTML에 있는 실제 서버 액션으로 관리자·담당자·현장 직원·업체·대리인·플랫폼 운영자 로그인 요청. 6개 모두 303으로 해당 화면 이동 및 세션 쿠키 발급 확인.
- 관리자·담당자·현장 직원 각각 행사 목록/팀/설정/감사 기록, 3개 행사의 개요/대표단/명단/서비스/업체/일정/변경 이슈/동의 화면을 인증된 HTTP 요청으로 확인. HTTP 200, 확인한 응답에서 서버 오류 없음.
- 업체 홈/계정/처리 내역, 대리인 홈/항공/일정/메시지/배정된 대표단 4개 상세, 플랫폼 운영자 홈/DB 점검도 동일하게 확인. 준비 화면은 정상 기능 통과로 취급하지 않음.
- 실제 DB에 독립 테스트 계정과 데이터를 생성하는 기존 통합 테스트로 조직·대표단 격리, 현장 직원 생성 제한, 민감정보, 항공 변경 영향/참가자 변경 영향, 조정 담당 재배정, 비공개 일정, 자체 일정 수송 생성 검증. 기존 81개와 메뉴 회귀 4개, 총 85개 통과.
- 데모 데이터 관계/구성 검사 5개 통과. 배포 빌드 통과. 변경 파일 ESLint 검사 통과.

## 발견한 문제와 수정

1. 대리인 ‘항공’과 ‘내 일정’ 메뉴가 구현 예정이라는 준비 화면으로 연결됨. 대표단 상세에는 이미 해당 기능이 있음. 기존 대표단 선택 목록을 재사용해 각 상세 화면의 서비스/일정 위치로 연결. 별도 요청·일정 편집 로직을 중복 구현하지 않음.
2. 대표단 목록 조회 실패를 ‘배정 없음’으로 표시하던 문제 수정. 조회 오류를 오류로 전달해 빈 배정과 구분. 새 안내 문구는 한국어/영어 메시지 파일에 추가.

## 검증 한계와 남은 항목

- 연결된 브라우저가 없어 실제 브라우저 클릭·모바일 레이아웃·자바스크립트 실행·앵커 스크롤의 시각 확인은 하지 못함. HTTP 화면 확인과 DB 통합 테스트를 브라우저 E2E 결과로 표현하지 않음.
- 공용 데모 데이터의 참석 회신/동의/예약 상태를 바꾸거나 파기하지 않음. 상태 변경 검증은 기존 독립 통합 테스트에서 수행.
- 대리인 메시지함과 업체 처리 내역은 기존 미구현 범위로 유지. 이번 수정은 항공·일정 메뉴에서 이미 구현된 화면으로의 진입 복구.
- 전체 ESLint에는 기존 오류 6개와 경고 2개가 남음: 대표단/행사 화면의 따옴표 표현 4개, 자체 일정 입력의 렌더 중 `Date.now()` 1개, 모바일 훅의 effect 내 상태 설정 1개. 변경 파일에는 오류 없음. 관련 없는 코드 전면 수정은 하지 않음.
