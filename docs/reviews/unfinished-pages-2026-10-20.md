## 검증

- 전체 자동 테스트 103개 통과. 새 테스트는 명단 검색/행사 범위, 자체 일정 수송 방향, 항공 데모 범위/일반 업체 보존, 설정 권한/입력/실제 영향 행 판정, 메시지함 본인 범위/언어, 운영사 데모 범위/개인정보 비출력.
- 운영 빌드와 변경 파일 ESLint 검사 통과.
- 로컬 운영 빌드에 실제 Supabase 세션으로 6개 역할 로그인. 관리자·담당자·현장 직원의 명단/검색/설정, 항공 업체 홈/처리 내역/내 정보/상태 필터, 대리인 공지, 운영사 현황을 HTTP 요청으로 확인.
- 업체 배정표(`event_vendor`)가 PCO 전용이라 업체에게 빈 결과가 나오는 것을 실제 검증에서 발견. 관리자 키나 권한 확장 없이, 업체가 RLS로 조회할 수 있는 서비스 정보를 기준으로 담당 범위를 계산하도록 수정. 항공편 `DEMO100`/`DEMO101` 및 `ICN` 표시 확인.
- 실제 설정 서버 액션으로 담당자의 동일 값 저장 성공과 현장 직원의 저장 거부 확인. 기존 값을 바꾸는 시나리오는 독립 테스트에서 검증.
- DB 마이그레이션·시드 재실행 없음. 가상 데모 조직의 행사 3개·대표단 6개·참가자 18명·서비스 31건 유지.

## 범위와 제한

- 메시지함은 현재 게시 공지와 일정 조정 요청의 조회함이다. 채팅·메일 발송·읽음 이력 저장은 포함하지 않는다.
- 설정 변경은 기준 정보를 저장한다. 기존 예약/서비스 상태의 자동 재계산이나 변경 이슈 생성은 수행하지 않는다. 의전 등급의 기존 기본값 JSON은 보존한다.
- 업체 내 정보는 본인 소속/역할 조회다. 계정 정보 변경·직원 초대는 포함하지 않는다. 서비스가 아직 등록되지 않은 업체 배정은 표시하지 않는다.
- 운영사 인증은 기존 임시 로그인 유지. 데모가 아닌 실제 조직의 현황·개인정보를 추가 노출하지 않는다.
- 실제 브라우저가 연결되지 않아 자바스크립트 상호작용·모바일 화면의 시각 검증은 미수행. HTTP 화면 및 서버 액션 확인을 브라우저 E2E로 표현하지 않는다.
- 기존 코드 전체 ESLint 오류 6개·경고 2개는 이번 기능 범위 밖이다. 변경 파일의 검사는 통과했다.
